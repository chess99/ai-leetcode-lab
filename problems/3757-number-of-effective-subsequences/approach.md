## Terra 失败交接与复杂度根因

Terra 首次远判结果为 **Time Limit Exceeded**。其数学方向（补集、SOS DP、容斥）是正确的，但实现有两个关键常数问题：

1. 状态位数取 `full.bit_length()`，而不是 `full` 中真正出现的二进制位数。若最高位很高但活跃位稀疏，仍会无谓分配并遍历接近 `2^20` 个状态。
2. 对每个非空缺失位集合都执行一次 `pow(2, count, MOD)`。最坏有 `2^20-1` 次模幂，每次还需 `O(log n)` 次乘法，这是超时的主要根因。

本实现先把实际出现的 `K = popcount(full)` 个位压缩到 `[0, K)`，再用 SOS DP 求子掩码计数；所有 `2^i mod MOD` 只预计算一次。SOS 转移按连续块遍历，也消除了原实现内层逐状态判断位是否为 1 的分支。

## 算法

把“删除的下标集合”换成它的补集“保留的下标集合”。二者一一对应。删除有效，当且仅当保留元素的按位或不等于全数组按位或 `full`。

压缩 `full` 中的 `K` 个活跃位。令 `cnt[mask]` 表示压缩后数值恰为 `mask` 的元素个数。经过子集和（SOS DP）后：

```text
cnt[mask] = 数值是 mask 子掩码的元素个数
```

枚举非空位集合 `missing`，表示这些位在保留集合的按位或中全部缺失。此时可保留的元素必须都是 `allBits XOR missing` 的子掩码，共有 `cnt[allBits XOR missing]` 个下标；这些下标的任意子集都合法，因此方案数为：

```text
2 ^ cnt[allBits XOR missing]
```

对“至少缺失一个活跃位”应用容斥：`missing` 大小为奇数时加，偶数时减。空保留集合自然被正确计入；删除空集合对应保留全部元素，其按位或仍为 `full`，不会被计入。

## 正确性证明

记原数组所有下标的集合为 `U`，全数组按位或为 `full`。

**引理 1：** 删除集合 `D` 有效，当且仅当其补集 `R = U \\ D` 的按位或缺失 `full` 的至少一个活跃位。

证明：删除后剩余数组恰由 `R` 中元素组成。其按位或不可能含有 `full` 之外的位，因此它严格小于 `full`（按题意即强度严格减少）当且仅当 `full` 中至少一位不再出现。证毕。

**引理 2：** 对任意非空活跃位集合 `S`，所有这些位都在 `R` 的按位或中缺失的保留集合数量为 `2 ^ cnt[allBits XOR S]`。

证明：某元素可被放入 `R`，当且仅当它不含 `S` 中任一位，即其压缩掩码是 `allBits XOR S` 的子掩码。SOS DP 给出的 `cnt` 正是此类元素下标数。每个下标可独立选择保留或不保留，所以共有相应的二次幂个集合。证毕。

**定理：** 算法返回且仅返回有效删除子序列的数量。

证明：由引理 1，目标是统计至少缺失一个活跃位的保留集合。算法对每个非空缺失位集合使用引理 2 的计数，并按集合大小奇加偶减；由容斥原理，每个至少缺失一位的保留集合恰计一次，未缺失任何位的集合计零。补集映射是一一对应，故所得正是有效且非空删除子序列的数量。证毕。

## 复杂度

令 `K = popcount(full) <= 20`，`P` 为输入所有数的二进制 1 的总数（`P <= 20n`）。

- 时间复杂度：`O(P + K * 2^K + n)`；最坏可写为 `O(nK + K * 2^K)`。
- 空间复杂度：`O(2^K + n)`，分别用于 SOS 状态和二次幂表。

与 Terra 版本相比，容斥阶段由 `O(2^K log n)` 次模运算降为 `O(2^K)` 次数组查询，且稀疏活跃位时状态数从按最高位决定改为按真实活跃位决定。

## 边界与本地验证

- `n = 1`：只能删除唯一元素，答案为 1。
- 重复元素按下标分别选择；例如 `[8, 8]` 只有全删有效。
- 保留集合可以为空，对应删除全部元素，应计入一次。
- 数值最高位很高但活跃位少时，位压缩避免虚假状态膨胀。
- 模运算只影响计数，不影响容斥符号，最终统一取模。

本地验证使用了与本算法独立的暴力 oracle：对短数组枚举所有非空删除掩码，直接重新计算剩余元素的按位或。

- 题目 4 个样例全部通过。
- 穷举长度 `1..6`、元素值 `1..6` 的全部 `55,986` 个数组，逐例与 oracle 一致。
- 使用固定随机种子 `3757` 生成 `10,000` 个数组（长度 `1..12`，数值覆盖至 12 个二进制位），逐例与 oracle 一致。
- 使用固定随机种子 `4134` 生成 `n = 100000` 的最大长度输入，并显式加入 `(1 << 20) - 1` 使活跃位数达到上限 `K = 20`。本机单次运行耗时 `1.244s`，返回 `646667019`，处于 `[0, 10^9+7)`；未出现内存异常。
