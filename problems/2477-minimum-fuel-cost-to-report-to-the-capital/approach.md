# 解题思路

> 作者：Codex Desktop · gpt-5.6-terra · medium（terra-medium）

## 思路

## 核心观察

把树以首都 `0` 为根。任意非首都城市 `u` 的整棵子树中的代表，最终都必须经过唯一的一条边 `u -> parent[u]` 离开子树。若这棵子树共有 `people` 名代表，那么无论子树内部怎样拼车，穿过这条边至少需要 `ceil(people / seats)` 辆车；让所有代表在 `u` 汇合后共同上车即可达到该下界。因此每条向父节点的边可以独立累加这项油耗。

## 算法

1. 建立无向邻接表，从 `0` 迭代遍历树，记录每个节点的父节点和根到叶的访问顺序。
2. 初始化每个城市的代表数为 `1`。
3. 按访问顺序的逆序处理除首都外的节点。此时其所有子树代表已汇总到该节点：
   - 将 `(representatives[u] + seats - 1) // seats` 加入答案；
   - 将 `representatives[u]` 累加给父节点。
4. 首都没有向上行驶的道路，不计入油耗，返回累计值。

使用显式顺序而非递归 DFS，避免深度为 `10^5` 的链状树触发递归深度限制。

## 正确性证明

对任意非首都节点 `u`，设其子树有 `k` 名代表。树中从该子树前往首都的唯一出口是边 `(u, parent[u])`，每辆车最多载 `seats` 人，所以至少要有 `ceil(k / seats)` 辆车通过该边，必然消耗这么多油。

算法在逆序处理中已经汇总了 `u` 的全部子树代表，恰好为该边增加 `ceil(k / seats)` 的油耗；随后把这 `k` 名代表交给父节点。代表在 `u` 汇合并按容量装车能够实现该数量，因此这条边的下界可达。所有非首都节点各对应一条不同的向上边，逐边累加的可达下界就是全局最少油耗，故算法正确。

## 复杂度分析

- 时间复杂度：`O(n)`，每个节点和每条道路仅处理常数次。
- 空间复杂度：`O(n)`，用于邻接表、父节点、遍历顺序和代表数。
