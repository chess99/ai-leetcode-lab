## 思路

先统计每种难度任务的出现次数。不同难度不能在同一轮完成，因此可以分别求每个频次所需的最少轮数再相加。

若某种难度只出现一次，不可能组成包含两或三个任务的一轮，直接返回 `-1`。对于频次 `count >= 2`，尽量使用三个任务一轮，最少轮数为向上取整的 `count / 3`，即 `(count + 2) // 3`。当余数为 `1` 时，把一个“三个一轮”和剩余一个调整成两个“两个一轮”即可，轮数仍等于该公式。

### 正确性

每轮最多完成三个任务，所以处理某一难度的 `count` 个任务至少需要 `ceil(count / 3)` 轮。

对于 `count >= 2`：余数为零时全部按三分组；余数为二时最后两项组成一轮；余数为一且 `count >= 4` 时，将最后四项分成两组各两个。三种情况下都能恰好用 `ceil(count / 3)` 轮完成，达到下界。只有 `count = 1` 无法分组。

各难度的任务彼此不能混合，算法把每种难度的独立最优轮数相加，因此得到全局最少轮数。

## 复杂度

- 时间复杂度：`O(n)`，统计频次并遍历所有不同难度。
- 空间复杂度：`O(n)`，最坏情况下哈希表保存所有任务难度。

## 边界条件与本地验证

- 任一难度只出现一次：整体立即无解。
- 频次分别为 `2`、`3`：都只需一轮。
- 频次模三余一：使用两个二任务轮替代一个三任务轮加单项。
- 多种难度：分别计算后累加。
- 本地验证覆盖两个题目样例，结果为 `4`、`-1`，并覆盖频次 `2`、`3`、`4`、`7` 和混合难度场景。
