# 解题记录

- AI 客户端：Codex Desktop；模型：gpt-5.6-terra；推理档位：medium；Profile：terra-medium；轮次：1
- 升级交接：`terra-medium -> sol-medium`；接手模型：`gpt-5.6-sol`；推理档位：`medium`

## 失败根因

`terra-medium` 候选的交集计数与 Jaccard 公式正确，远程 WA 的唯一差异是文档对 `74,90`：真实比值为 `1/32 = 0.03125`，候选用 Python `f"{value:.4f}"` 得到 `0.0312`，期望为 `0.0313`。根因是 Python 格式化在精确半界采用 ties-to-even（五成双），而本题判题采用 `ROUND_HALF_UP`（半界进位）。

新候选完全不用浮点数或 `Decimal`：对 `common * 10000` 除以 `union` 做整数商余数；若 `2 * remainder >= union`，整数商加一，再把它拆成整数部分和四位小数。这精确实现十进制四位 `ROUND_HALF_UP`，不会受二进制浮点误差影响。

原候选在高重叠数据上还可能进行最多 `500 * C(500, 2) = 62,375,000` 次 Python 二元组哈希表更新。虽非本次 WA 根因，升级候选同时用下述自适应算法消除这项性能风险。

## sol-medium 新算法：自适应倒排 / 集合求交

先建立倒排表 `word -> 包含该词的文档 ID 列表`，同时计算倒排路径需要的精确计数更新次数
`W_inv = sum_word C(freq(word), 2)`。再根据文档长度计算两两集合求交最多需要检查的元素数
`W_pair = sum_{i<j} min(len(docs[i]), len(docs[j]))`。

- 当 `8 * W_inv <= W_pair` 时，重叠确实稀疏。遍历每个词的文档列表，将对应文档对的交集计数加一。计数存在定长数组中，用 `id1 * n + id2` 定位，避免二元组哈希表的额外开销。
- 否则，预先把文档转换成集合，枚举至多 `C(500, 2)` 个文档对，用 Python 底层 C 实现的集合交集直接得到交集大小。高重叠时，这避免数千万次 Python 字典更新。

阈值 8 只影响选择哪条等价的精确计算路径，不影响答案。两条路径都只输出交集非零的文档对，并将 `intersection / (len1 + len2 - intersection)` 用纯整数 `ROUND_HALF_UP` 格式化为四位小数。

## 正确性证明

对任意文档对 `(i, j)`：

1. 倒排路径中，每个同时出现在文档 `i`、`j` 的词，其倒排列表恰好包含一次 `i` 和一次 `j`，因此给该文档对的计数恰好贡献 1。题面保证单个文档内元素不同，所以不会重复贡献。没有同时出现的词不会贡献，最终计数恰为 `|docs[i] ∩ docs[j]|`。
2. 集合路径直接计算 `len(set(docs[i]) & set(docs[j]))`，按集合交集定义也恰为 `|docs[i] ∩ docs[j]|`。
3. 两条路径随后都用 `|A ∩ B| / (|A| + |B| - |A ∩ B|)`。分母等于 `|A ∪ B|`，故该有理数正是题目定义的 Jaccard 相似度。
4. 令 `q, r = divmod(10000 * common, union)`。精确的缩放值为 `q + r/union`；当且仅当 `2r >= union` 时其小数部分至少为 `0.5`，整数进位正好实现 `ROUND_HALF_UP`。拆分进位后的整数即可得到正确的四位小数字符串。
5. 仅当交集大于 0 时输出，所以输出集合也完全符合要求。

因此无论自适应条件选择哪条路径，算法都返回且仅返回所有相似度大于 0 的文档对及其正确相似度。

## 复杂度

设文档数为 `n`，总元素数为 `M`，不同词数为 `U`，`f_w` 为词 `w` 的文档频次，文档最大长度为 `L`。

- 公共预处理：时间 `O(M + n log n)`，空间 `O(M)`。
- 倒排路径：时间 `O(M + sum_w f_w^2 + n^2)`，定长计数表空间 `O(n^2)`。
- 集合路径：时间 `O(M + sum_{i<j} min(|D_i|, |D_j|))`，集合空间 `O(M)`。

因 `n, L <= 500`，两两路径至多处理 `C(500, 2)` 对、每对至多 500 个元素；自适应选择能避开高重叠倒排表最差情形中的大量 Python 哈希更新。

## 边界条件与本地验证

- 少于两个文档直接返回空数组；空文档与任何文档交集为零，不输出。
- 全部文档互不相交时，倒排计数均为零，返回空数组。
- 完全相同的非空文档相似度为 `1.0000`；包含关系、负整数和零均按普通集合元素处理。
- 精确半界反例 `1/32` 输出 `0.0313`，不会落入 Python 默认的 `0.0312`。
- 题面保证文档内元素不同；算法不依赖词值范围。
- 本地验证覆盖官方样例、远程失败反例 `1/32`、空输入/空文档、无交集、完全相同、包含关系，并以独立暴力 oracle 进行随机对拍及 500×500 高重叠性能测试。
