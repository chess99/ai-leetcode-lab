# 解题记录

## Terra 失败交接

上一候选为 `terra-medium`（`gpt-5.6-terra`，medium）。它先连接图书表与未归还借阅，再按
`book_id`、标题、作者、类型、出版年份和总副本数这组宽键聚合。该查询语义正确，但在末例
`Time Limit Exceeded`。主要性能风险是：每条未归还借阅都先携带图书的多个文本字段进入聚合，
使排序/哈希键、临时表和数据搬运远宽于实际需要；借阅记录多时，这部分开销会被显著放大。

本候选身份为 `sol-medium`（`gpt-5.6-sol`，reasoning effort: medium），针对上述宽聚合改为
“窄表预聚合，再回表取展示列”。

## SQL 方案

1. 派生表只扫描 `borrowing_records` 中 `return_date IS NULL` 的记录，并仅按整数
   `book_id` 分组，以 `COUNT(*)` 得到每本书的当前未归还记录数 `current_borrowers`。
2. 将至多每本书一行的聚合结果连接到 `library_books`。
3. 在连接条件中要求 `current_borrowers = total_copies`，只保留可用副本数为零的书。
4. 按当前借阅数降序、标题升序输出。

## 正确性论证

对任意书籍 `b`，派生表中 `b` 的 `current_borrowers` 恰好等于借阅表中满足
`book_id = b.book_id` 且 `return_date IS NULL` 的记录数，因此它正是题目定义的当前借阅数。

- 若该数等于 `b.total_copies`，则可用副本数为
  `b.total_copies - current_borrowers = 0`，连接条件成立，书籍被输出。
- 若该数小于或不等于 `b.total_copies`，连接条件不成立，书籍不会被输出。
- 若没有未归还记录，派生表中没有该书的行，内连接自然排除它；这也符合“当前被借出且无可用副本”的要求。

所以结果恰好包含全部且仅包含当前无可用副本的书。最后的两个排序键与题目要求一致。

## 复杂度

设借阅记录数为 `r`，其中未归还记录数为 `a`，有未归还记录的不同书籍数为 `k`，最终结果数为
`m`。过滤需扫描至多 `r` 行；哈希聚合通常为 `O(a)`，若采用排序聚合则为
`O(a log a)`；连接通常为 `O(k)`，结果排序为 `O(m log m)`。聚合空间为 `O(k)`。

相比 Terra 方案，渐进复杂度量级未改变，但聚合键从包含多个 `varchar` 字段的整本书宽行缩减为单个
整数 `book_id`，且图书展示字段只在聚合完成后的至多 `k` 行上连接，避免对 `a` 条明细重复搬运和
分组宽字段。这正是末例下的主要性能改进。若存在 `(return_date, book_id)` 或适合过滤并按
`book_id` 读取的索引，数据库还可进一步降低扫描和聚合成本；方案不依赖该索引才能保持正确。

## 边界条件与本地验证

- 已归还记录在聚合前被过滤，不会计数。
- 没有当前借阅的书不会出现在派生表中。
- 当前借阅数少于总副本数时仍有可用副本，必须排除。
- 多本书当前借阅数相同时按标题升序；标题也相同的相对顺序题目未要求。
- `COUNT(*)` 统计的是未归还借阅记录，避免依赖某个可空业务列；题面中记录主键也保证每条交易只计一次。
- 题目业务约束暗含当前借阅数不会超过总副本数；即使出现不一致数据，本方案使用等号，仍不会把
  “负可用副本”误称为“无可用副本”，与题目要求及原候选语义一致。

本地使用 SQLite 内存库执行题面样例，并补充已归还记录、无当前借阅、未借满、并列排序和宽文本字段
场景；核对输出列、计数、筛选和顺序。所用语法（派生表、`COUNT(*)`、`IS NULL`、连接与排序）均为
MySQL 支持的标准用法。
