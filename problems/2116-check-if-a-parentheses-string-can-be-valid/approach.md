## 算法与思路

有效括号字符串的长度一定是偶数，因此先排除奇数长度。

随后进行两次贪心扫描：

1. 从左向右扫描，把所有未锁定位置暂时视为左括号。这样可以得到每个前缀所能拥有的最大左括号余量；若余量变成负数，说明这个前缀中锁定的右括号过多，无论如何修改都无法有效。
2. 从右向左扫描，把所有未锁定位置暂时视为右括号。对称地检查每个后缀是否能提供足够的右括号；若余量变成负数，则锁定的左括号过多。

两次检查都通过，就存在一种给未锁定位置分配括号的方式使整个字符串有效。

## 正确性

从左向右检查时，未锁定位置全部当作左括号已经是维持前缀不出现负余额的最有利选择。如果即使如此某个前缀的余额仍小于零，那么该前缀必然有无法匹配的锁定右括号，因此无解。检查通过则保证每个前缀都有能力提供足够的左括号。

从右向左的检查完全对称：未锁定位置全部当作右括号是让后缀拥有足够右括号的最有利选择。检查通过保证每个后缀都有能力匹配其中的锁定左括号。

偶数长度保证左右括号的总数可以相等，而两个方向的检查分别排除了前缀右括号过多和后缀左括号过多的唯一两类障碍。因此两次检查均通过当且仅当可以得到有效括号字符串。

## 复杂度

- 时间复杂度：`O(n)`，对字符串进行两次线性扫描。
- 空间复杂度：`O(1)`，只维护余额计数。

## 边界条件与本地验证

- 奇数长度：直接返回 `false`。
- 全部位置锁定：等价于检查原字符串是否有效。
- 全部位置未锁定：偶数长度时总能重新分配成有效括号串。
- 本地验证覆盖四个题目样例，以及锁定右括号导致前缀非法、锁定左括号导致后缀非法和最短偶数长度等场景。
