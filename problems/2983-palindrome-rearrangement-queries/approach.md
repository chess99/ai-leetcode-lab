## 算法

令 `m = n / 2`，把原串拆成：

- `L = s[0:m]`
- `R = reverse(s[m:n])`

这样原串成为回文串等价于每个位置都有 `L[i] == R[i]`。原查询的右半区间 `[c,d]` 映射到 `R` 上是 `[n-1-d,n-1-c]`。记左、右两个可重排区间分别为 `I`、`J`。

预处理两类信息：

1. `L`、`R` 各自的 26 维字符计数前缀和；
2. `L[i] != R[i]` 的失配前缀和。

每个查询分两步判定：

1. `I ∪ J` 之外的两侧字符都不可改变，因此那里不能存在任何失配。用失配前缀和及容斥在常数时间内检查。
2. 统计 `L[I]` 和 `R[J]` 的字符库存。位置 `I \ J` 的右侧固定，所以必须从 `L[I]` 中扣掉 `R[I \ J]`；同理，从 `R[J]` 中扣掉 `L[J \ I]`。如果库存不足则失败。扣除后只剩交集 `I ∩ J` 中两侧都可改变的位置，两份剩余字符多重集必须完全相同。

实现中特别将查询所需的前缀行在进入 26 字母循环前全部缓存。旧候选在字母循环内部反复构造完整的 26 维区间计数，实际工作量接近每查询 `26²` 且产生大量临时列表，这是超时的直接原因。

## 正确性证明

设一次查询映射后的可重排区间为 `I`、`J`。

首先，`I ∪ J` 外的任一对称位置，其 `L`、`R` 两个字符均不属于可重排区间，查询不能改变它们。因此若该处原本失配，不可能得到回文串；若所有这些位置都匹配，则它们无需处理。第一步判定恰好检查了这个必要且充分条件。

接着考虑 `I ∪ J` 内：

- 对于 `I \ J`，只有 `L` 一侧可重排，最终字符被固定的 `R` 一侧唯一决定。因此必须从 `L[I]` 的库存中逐字符提供 `R[I \ J]`，库存不足时必不可能；库存足够时可以把这些所需字符放到对应位置。
- 对于 `J \ I` 完全对称，必须从 `R[J]` 提供 `L[J \ I]`。
- 完成上述强制匹配后，尚未安排的位置恰为 `I ∩ J`，并且每个位置的两侧都可重排。它们能够逐对相等，当且仅当左右剩余字符多重集相同：相同则按任意相同顺序放置即可，不同则至少有一种字符无法配对。

算法逐字符检查库存非负及两份剩余多重集相等，所以第二步也是必要且充分的。结合区间外检查，算法返回 `true` 当且仅当本次查询可以把原串变为回文串。

## 复杂度

- 预处理：时间 `O(26n)`（实际每个位置复制一行 26 维计数），空间 `O(26n)`。
- 每个查询：时间 `O(26)`，只使用 `O(1)` 额外空间；全部查询为 `O(26q)`。

## 边界条件

- `I`、`J` 完全分离：交集计数为零，两段之间及外部所有固定失配都会被第一步发现。
- 两区间部分重叠、端点相接或一方包含另一方：交集只扣除一次，差集的固定需求按字符准确计算。
- 两区间完全相同：没有单侧固定需求，只需两边区间字符多重集相同。
- 字符总数看似相同但某侧不足：剩余库存为负时立即判为不可行。

## 本地验证

使用与本算法独立的穷举 oracle：对两个查询子串分别枚举所有不同排列，直接拼接并检查回文；覆盖题面样例，并对小规模随机字符串、随机合法查询进行充分对拍。另执行 Python 语法检查。
