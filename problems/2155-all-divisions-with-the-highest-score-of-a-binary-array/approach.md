## 算法与思路

用 `left_zeros` 记录分割线左侧的零数，用 `right_ones` 记录右侧的一数。分割下标为 `0` 时，左侧为空，所以 `left_zeros = 0`；右侧是整个数组，所以 `right_ones = sum(nums)`。

依次考察从 `0` 到 `n` 的每条分割线，当前得分就是两者之和。若得分高于历史最高分，就重置答案；若等于最高分，就追加当前下标。分割线右移一位时，根据跨过的元素更新左侧零数或右侧一数。

## 正确性

考察分割下标 `i` 时，循环变量满足以下不变式：`left_zeros` 恰好是 `nums[0:i]` 中零的个数，`right_ones` 恰好是 `nums[i:n]` 中一的个数。因此算法计算的和正是下标 `i` 的分组得分。

分割线从 `i` 移到 `i + 1` 时，只有 `nums[i]` 改变所属组：它为零时左侧零数加一，它为一时右侧一数减一，所以不变式继续成立。算法遍历了全部 `n + 1` 个合法下标，并只保留达到全局最高分的下标，因此返回结果正确。

## 复杂度

- 时间复杂度：`O(n)`，初始化和遍历均为线性时间。
- 空间复杂度：`O(n)`，最坏情况下答案包含全部分割下标；除返回值外额外空间为 `O(1)`。

## 边界条件与本地验证

- 分割下标可以为 `0` 或 `n`，循环会同时考察两端的空数组情况。
- 全为零：最优分割位于 `n`。
- 全为一：最优分割位于 `0`。
- 多个下标并列最高分：全部加入答案。
- 本地验证覆盖三个题目样例，结果分别为 `[2,4]`、`[3]`、`[0]`，并覆盖单元素和多个最优下标场景。
