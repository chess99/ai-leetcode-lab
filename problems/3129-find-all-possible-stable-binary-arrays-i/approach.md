## 思路

题目的子数组条件等价于：数组中每一段连续相同元素的长度都不超过 `limit`。因此可以先决定 0 段与 1 段各有多少段，再计算每种段长分配。

令 `compose(n, k)` 表示把 `n` 拆成 `k` 个有序正整数之和、且每个数不超过 `limit` 的方案数。计算它时使用动态规划：

- `previous[s]` 表示使用上一段数、总和为 `s` 的方案数；初始 `previous[0] = 1`。
- 增加一段后，`current[s] = sum(previous[s-x])`，其中 `1 <= x <= limit`。
- 对 `s` 从小到大维护滑动窗口，可以在线性时间完成一层；记录每层的 `current[n]`，便得到所有 `compose(n, k)`。

0 段和 1 段必须交替，因而它们的段数只可能有三种关系：

1. 段数同为 `k`：可以从 0 开始，也可以从 1 开始，贡献 `2 * compose(zero,k) * compose(one,k)`。
2. 0 段比 1 段多一段：首尾都为 0，贡献 `compose(zero,k) * compose(one,k-1)`。
3. 1 段比 0 段多一段：首尾都为 1，贡献 `compose(zero,k-1) * compose(one,k)`。

把以上互斥情况求和并对 `1_000_000_007` 取模即可。

## 正确性证明

任意稳定数组的每个同值连续段长度至多为 `limit`，否则该段自身包含一个长度超过 `limit` 且只有一种元素的子数组；反之，如果所有同值连续段长度都至多为 `limit`，任何长度超过 `limit` 的子数组都不可能落在单个同值段内，所以必然同时包含 0 和 1。因此稳定性与段长上界完全等价。

固定 0 段数 `a` 和 1 段数 `b` 后，0 的段长恰好对应一个由 `compose(zero,a)` 计数的有序拆分，1 同理，两者选择相互独立。二进制数组的相邻段取值不同，所以只有 `a=b`、`a=b+1` 或 `b=a+1` 能交替排列；前者有两个起始值，后两者的起始值唯一。算法枚举并相加了这三类，且不同段数或起始值对应的数组互不相同。因此算法不重不漏地计数了所有稳定数组。

## 复杂度

计算某个总数 `n` 的所有有界拆分需要 `O(n^2)` 时间和 `O(n)` 工作空间；保存各段数的最终方案数也为 `O(n)`。总时间复杂度为 `O(zero^2 + one^2)`，额外空间复杂度为 `O(zero + one)`。在本题 `zero, one <= 200` 的约束下，内存只包含少量长度至多 201 的整数数组，不再随四维递归状态数量增长。

## 边界条件

- `limit >= n` 时，有界拆分自然退化为普通正整数有序拆分，无需特判。
- `limit = 1` 时，每种数字的每段长度只能为 1，只有严格交替且两种数量之差不超过 1 时有解。
- `compose(n,0)=0`（题目中 `n` 为正），所以段数相差一的公式在另一种数字为 0 段时不会误计；实现保留了索引 0 作为统一边界。
- 所有动态规划值和最终答案均按模数计算；滑动窗口即使暂时为负，Python 的取模仍得到标准非负余数。

## 本地验证

使用与本算法独立的暴力枚举 oracle：枚举固定 0/1 数量的所有二进制排列，直接检查最长同值连续段。穷举覆盖 `zero, one = 1..7`、`limit = 1..8` 的 392 组参数，另以固定种子完成 500 组 `zero, one <= 9` 的随机对拍；样例结果分别为 `2`、`1`、`14`。最大约束 `zero=one=limit=200` 的本地计时为约 0.12 秒（启用 `tracemalloc`），候选执行期间测得峰值约 24.8 KiB；原失败证据 `zero=59, one=55, limit=97` 约 0.001 秒完成。以上均为本地验证，不代表远端 Accepted。
