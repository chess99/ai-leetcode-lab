## sol-high → sol-xhigh 交接与失败根因

`sol-high` 候选按 1430 个九叶树形逐一处理，并在每个树形内枚举宝石集合和两侧排列。它已有样例及小规模 oracle 证据，但可追溯的第一次正式提交结果为 `Time Limit Exceeded`：通过 112/114 个用例后，在

```text
gem = [321113,909148,2108330,853584,1000839,674651,1585598,38486,42347102]
p = 2
target = 1
```

超时，期望值为 `518918400`。随后 `sol-high` 以“first submission was not Accepted; escalate to the next profile”为由 defer。

根因是算法把“树形”放在最外层，导致同一个较小子树和局部上下文在许多完整树形中被反复计算。九叶时约有 2595 万组半排列，每组还要扫描 4～5 个宝石，Python 实际执行的是上亿次模运算。失败用例的模数又是 2；任意记录串均以 `9` 结尾，本可直接判断，却仍走了最坏枚举路径。因此这是明确的性能失败，而不是该次远程反馈指出的答案错误。

## sol-xhigh 算法：唯一平衡边分解

一棵含叶集合 `M` 的树，其记录串长度只取决于集合：

```text
len(M) = sum(len(str(gem[i]))) + 4 * |M| - 2
```

对于 `n <= 6`，直接使用子集 DP。对于 `7 <= n <= 9`，为每棵完整树唯一选一条平衡边：

1. 从根开始，只要某个孩子含有超过 6 个叶子，就下降到该孩子。这样的孩子至多一个。
2. 停止后两个孩子都至多含 6 个叶子；选择叶子数较多的孩子，数量相等时选择左孩子。

当前节点始终含有超过 6 个叶子，所以选中子树含 `4..6` 个叶子。把它整体折叠成一个洞 `H`，剩余部分成为“带洞上下文”。于是每棵树被唯一拆成：

```text
带编号的 4..6 叶子子树 S + 带其余宝石的上下文 (P + H + Q)
```

### 子树余数 DP

`dp[M][r]` 记录使用集合 `M` 能组成多少棵有序满二叉子树，其记录串模 `p` 为 `r`。叶子直接计算 `"1" + gem[i] + "9"`。非叶树枚举根的有序划分 `A + B = M`，若左右余数为 `a,b`，则

```text
r = 10^(len(A)+len(B)+1)
    + a * 10^(len(B)+1)
    + b * 10
    + 9                         (mod p)
```

所有至多五叶的状态缓存复用；六叶状态按集合临时生成、匹配后释放。

### 带洞上下文匹配

枚举折叠后的结构、洞位置和洞外宝石排列，并只保留按上述规则确实会选中该洞的结构。编译后的完整记录串为 `P + S + Q`，故

```text
full = rem(P) * 10^(len(S)+len(Q))
     + rem(S) * 10^len(Q)
     + rem(Q)                         (mod p)
```

当素数 `p` 不是 2 或 5 时，`10^len(Q)` 可逆，所以每个上下文只需反解一个所需的 `rem(S)`，再查 `dp` 计数，不枚举子树与上下文的笛卡尔积。

`p` 为 2 或 5 时，整个整数的模数只由末位 `9` 决定；`p == 1` 也一并作为防御性边界处理。满足目标时直接返回

```text
Catalan(n-1) * n!
```

否则返回 0。

## 正确性证明

### 引理 1：子集 DP 不重不漏地统计所有带编号有序满二叉子树

单叶状态显然唯一。任意非叶树的根都有唯一的左叶集合 `A` 和右叶集合 `B`；反过来，任意非空有序划分 `(A,B)` 与两棵对应子树能唯一组成一棵树。归纳假设保证左右状态正确，拼接公式又与 `"1" + left + right + "9"` 完全一致，因此 `dp[M]` 的余数和计数均正确。

### 引理 2：每棵 `7..9` 叶树都有唯一的所选平衡边，且子树大小为 `4..6`

含超过 6 个叶子的孩子不可能同时出现，因为整棵树至多九叶，所以每一步下降都是唯一的。停止节点含超过 6 个叶子，而两个孩子都至多六叶；较大孩子至少四叶。固定的“较大优先、相等选左”规则使最终边唯一。

### 引理 3：有效的“子树 + 上下文”与完整组装方案一一对应

按引理 2 折叠完整树的唯一所选子树，会得到算法枚举并通过筛选的唯一带洞上下文，宝石下标集合也随之唯一分开。反向把同样大小的任意带编号子树填回有效上下文后，所有叶子权重不变，平衡边选择仍会落在洞处，因而恢复唯一完整树。数值相同但编号不同的宝石仍属于不同集合或排列，不会被合并。

### 引理 4：余数匹配条件充要

上下文展开就是 `P + S + Q`，其模数由上述拼接等式精确给出。`p` 不是 2 或 5 时乘数 `10^len(Q)` 存在逆元，反解出的余数是唯一的；查询 `dp` 恰好加入所有且仅有满足目标的子树。特殊模数则由固定末位直接判定。

由引理 1～4，算法统计的方案与题目要求的组装方案一一对应，答案正确。

## 复杂度

记 `C_k` 为第 `k` 个 Catalan 数。子树 DP 的状态展开工作量上界为

```text
sum(k=1..6) C(n,k) * C_(k-1) * k!
```

九叶时主项为 `C(9,6) * C_5 * 6! = 2,540,160`。缓存仅保留至多五叶的状态，并同时保留一个六叶集合，空间上界对应约 25.8 万个余数项；实际余数相同会由计数器合并。

九叶时，大小为 4、5、6 的子树分别只有 34、30、20 个有效带洞结构；全部集合和洞外排列合计 614,880 个上下文。每个上下文扫描至多五个洞外宝石。相较上一候选按 1430 个完整树形重复排列，工作量和峰值空间都显著下降。

## 边界条件

- `n == 1`：子集 DP 返回唯一叶子串的判定结果。
- `p in {1,2,5}`：按固定末位 `9` 直接返回全体方案数或 0。
- `gem[i] == 0`：十进制长度为一位，不能当作空串。
- `gem[i] == 10^9`：使用原数的十进制长度，余数计算前可安全取模。
- 宝石数值相同：始终按下标分配和排列，保留题目要求的多重计数。
- 答案最大可达 `Catalan(8) * 9! = 518918400`。
