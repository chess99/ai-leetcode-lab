## 思路

构造前缀和 `prefix`，并把所有糖果按必须进食的顺序编号为 `1, 2, ...`。类型 `t` 的糖果编号闭区间为：

```text
[prefix[t] + 1, prefix[t + 1]]
```

到第 `d` 天为止一共经历 `d + 1` 天。每天至少吃一颗、至多吃 `cap` 颗，所以第 `d` 天可能覆盖的糖果编号闭区间为：

```text
[d + 1, (d + 1) * cap]
```

查询为真当且仅当这两个闭区间相交。

## 正确性证明

记目标区间为 `[L, R]`，第 `d` 天的可达编号区间为 `[A, B]`。

- 必要性：第 `d` 天之前至少已吃 `d` 颗，因此当天不可能吃到编号小于 `A = d + 1` 的糖；到当天结束最多吃 `(d + 1) * cap = B` 颗，因此也不可能吃到编号大于 `B` 的糖。若当天吃到目标类型，目标区间必与 `[A, B]` 相交。
- 充分性：若两区间相交，取交集中的编号 `x`。令前 `d` 天（第 0 天到第 `d-1` 天）的累计进食量为 `y = max(d, x - cap)`。由 `x <= (d + 1) * cap` 可得 `y <= d * cap`，且由 `x >= d + 1` 可得 `d <= y < x`，所以前 `d` 天能以每天 `[1, cap]` 颗安排到总量 `y`。第 `d` 天再吃 `x - y` 颗，这个数量也在 `[1, cap]`，因此当天会吃到第 `x` 颗糖。又因 `L <= x <= R`，它正是目标类型。

闭区间相交等价于 `L <= B` 且 `A <= R`。代回后第一项是 `prefix[t] + 1 <= (d + 1) * cap`，也即 `prefix[t] < (d + 1) * cap`。Terra 使用了 `prefix[t] <= ...`，在最大吞吐量恰好等于前置糖果数时产生 off-by-one：失败用例最多只能在第 2 天结束时吃完前 18 颗糖，类型 2 从第 19 颗才开始，因此答案必须为 `false`。

## 复杂度

前缀和预处理时间 `O(n)`、空间 `O(n)`；每个查询只做常数次算术和比较，时间 `O(1)`，全部查询为 `O(q)`。

## 本地验证

- 定向覆盖题面两个示例、真实失败用例、目标区间恰好在可达区间左右端点相交，以及两种刚好错开一颗的边界。
- 对长度 1 到 4、每类数量 1 到 3 的全部 120 个小数组，枚举类型、日期和日上限；独立 oracle 按天维护所有可能的累计进食量，并检查目标日实际进食编号是否与目标类型相交。
