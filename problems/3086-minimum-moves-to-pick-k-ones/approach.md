# 解题记录

## 交接与署名

- 初始候选：Codex Desktop / gpt-5.6-terra / medium（terra-medium）
- 当前修复：Codex Desktop / gpt-5.6-sol / medium（sol-medium）
- 失败证据：`nums=[1,0,1], k=2, maxChanges=0`，初始候选输出 `1`，正确答案为 `2`。

初始候选把“某个长度为 3 的窗口中 `1` 的数量”误当成连续 `1` 段长度；`[1,0,1]` 因而被错误套用了连续段公式。本次改为真正扫描最长连续 `1` 段。

## 算法

设所有现有 `1` 的下标依次为 `positions`。

一次修改可以在 Alice 位置之外任意造出一个 `1`，再交换一步送到 Alice 位置，因此每个新造的 `1` 固定花费 `2`。现有 `1` 移到 Alice 位置的花费等于下标距离。

先求最长连续 `1` 段，并令 `cheap = min(最长段长度, 3, k)`。选择该连续段的中间位置站立时：第一个 `1` 免费拾取，其余至多两个相邻 `1` 各花一步，所以拾取这 `cheap` 个 `1` 的总成本是 `cheap - 1`。超过 3 个后，新增现有 `1` 的边际成本至少为 2，不再优于修改。

- 若 `cheap + maxChanges >= k`，取 `cheap` 个连续段中的现有 `1`，其余全部修改，答案为 `cheap - 1 + 2 * (k - cheap)`（`cheap=0` 时前一项取 0）。
- 否则即使用完修改次数仍需 `needed = k - maxChanges` 个现有 `1`。此时最优解一定用完全部修改，因为超过局部 `cheap` 的现有 `1` 边际成本至少为 2。对每个包含 `needed` 个连续位置的窗口，把这些 `1` 都移动到窗口中位数；绝对距离和在中位数处最小。用位置前缀和在 `O(1)` 内计算每个窗口的距离和，再加上 `2 * maxChanges`，取最小值。

## 正确性证明

### 引理 1：每个通过修改得到并拾取的 `1` 的最小成本恰为 2

修改位置不能等于 Alice 所在位置，因此至少需要一次修改和至少一次相邻交换，成本至少为 2。选择 Alice 的任一合法相邻位置修改，再交换到 Alice 位置即可用 2 步完成，所以下界可达。

### 引理 2：成本严格小于 2 的现有 `1` 最多来自一个长度至多为 3 的连续段

相对 Alice 位置，只有距离 0 的 `1` 免费，距离 1 的 `1` 成本为 1；这样的下标只可能是 Alice 位置及其左右邻位，且被采用的 `1` 必须构成真实连续段。故其数量是 `min(最长连续 1 段, 3)`。选择该段中点能以总成本 `cheap - 1` 拾取它们。任何额外现有 `1` 的距离至少为 2，边际成本不小于修改。

### 引理 3：固定拾取 `needed` 个现有 `1` 时，存在最优解选择 `positions` 中的一个连续窗口，并在其中位数汇合

固定 Alice 位置后，应选择距离它最近的 `needed` 个现有 `1`；若选择集合跨过了一个未选位置，用中间的未选位置替换更远的已选位置不会增大成本。因此存在由位置序列中连续窗口构成的最优集合。对固定窗口，移动成本是到 Alice 位置的绝对距离和，该函数在窗口中位数处取得最小值。

### 定理：算法返回最少行动次数

若 `cheap + maxChanges >= k`，由引理 2 应先取所有边际成本小于 2 的现有 `1`，其余使用引理 1 的修改操作，算法公式最优。否则必须取至少 `k-maxChanges` 个现有 `1`；由引理 2，超过 `cheap` 后现有 `1` 不优于成本为 2 的修改，所以存在最优解用完全部修改，恰取 `needed` 个现有 `1`。算法依据引理 3 枚举了所有可能的最优窗口并计算其最小距离和，再加修改成本，故所得全局最小值即为答案。

## 复杂度

提取位置、扫描连续段和枚举窗口均为线性时间，时间复杂度 `O(n)`；位置数组和前缀和占用 `O(n)` 额外空间。

## 边界条件

- 数组中没有现有 `1` 时，由约束可知修改数足够，答案为 `2k`。
- `k=1` 且存在现有 `1` 时可直接站在该位置，答案为 0。
- `maxChanges=0` 时只枚举恰含 `k` 个现有 `1` 的窗口；`[1,0,1]` 的中位数距离和为 2。
- 连续段长度大于 3 时也只把 3 个视为低于修改成本的局部收益，其余按一般中位数窗口处理。
