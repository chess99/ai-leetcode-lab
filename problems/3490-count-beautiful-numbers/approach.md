## 思路

用 `count(r) - count(l - 1)` 转化为两个前缀计数。

一次数位 DP 同时统计所有可能的数位和。状态记录：当前位置、当前数位和、非零有效数字乘积中质因子 `2/3/5/7` 的指数、是否已经开始、是否出现过有效零，以及是否贴住上界。

十进制非零数字的质因子只可能是 `2/3/5/7`。本题最多 9 位，数位和至多 81；判断乘积能否被数位和整除，只需把四种指数分别封顶到 `6/4/2/2`（不超过 81 的数分别最多需要这些指数）。预处理每个数位和的质因数需求；若它还含其他质因子，非零数字乘积不可能被它整除。若数字开始后出现过零，则乘积为零，而数位和为正，可直接计数。

前导零既不令数字“开始”，也不设置零标记，因此不会把短数字误当成含零数字；全程未开始的状态代表整数 0，末尾排除。

## 正确性证明

对 DP 扫描到任意位置后的状态作归纳：`digit_sum` 等于已经选择的有效数字之和；`has_zero` 当且仅当有效部分出现过零；若未出现零，四个指数分别等于有效数字乘积中 `2/3/5/7` 的指数（超过判断所需最大值时封顶）。初始空前缀显然满足；追加前导零不改变有效部分，追加有效零只设置 `has_zero`，追加非零数字则按其唯一质因数分解增加对应指数，所以不变式保持。

到达末尾时，未开始的唯一状态是整数 0，正确排除。若 `has_zero`，有效数字乘积为 0，必能被正数位和整除。否则乘积只含 `2/3/5/7`：它能被数位和整除，当且仅当数位和不含其他质因子，且乘积的四个指数均不小于数位和的对应需求。终态判断恰好检查这两个条件。因此 `count(x)` 不重不漏地统计 `[1, x]` 的美丽整数，两个前缀之差即为 `[l, r]` 的答案。

## 复杂度

设十进制位数为 `d`，数位和上界为 `9d`，封顶指数状态数为 `7 * 5 * 3 * 3 = 315`。每个状态枚举 10 个数字，时间复杂度上界为 `O(d^2 * 315 * 10)`，空间复杂度为 `O(d^2 * 315)`；布尔状态只贡献常数因子。本题 `d <= 9`。

## 边界条件与本地验证

- `limit <= 0` 返回 0；整数 0 不计入答案。
- 前导零不参加乘积，数字内部或末尾的零令乘积变为 0。
- 数位和为 1、含质因子 `> 7`、以及指数刚好达到或超过需求均由统一终态判断处理。
- 本地用与候选逐状态对应的独立运行镜像验证：5 组官方样例/边界用例通过；1000 组随机小区间与逐数暴力 oracle 完全一致；最大约束 `[1, 999999999]` 得到 `670349658`，压力运行约 `0.042s`（Node.js 镜像计时）。当前机器没有可用的 Python 解释器，因此另对 Python 源码进行了完整人工语法与状态转移复核，但未声称本地 Python 实跑或远端 Accepted。
