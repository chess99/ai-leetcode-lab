## 思路

对每次查询，建立所有原始下标的列表，并按二元键 `(nums[index][-trim:], index)` 排序。所有裁剪后字符串长度相同，所以字符串字典序与它们的数值大小一致，前导 0 也能被正确保留。二元键的第二项是原始下标，恰好满足值相同时时下标较小者优先的规则。排序后第 `k - 1` 个下标就是该查询的答案。

## 复杂度

设数字个数为 `n`、查询数为 `q`、每个字符串长度为 `l`。每次查询排序为 `O(n log n)`，裁剪键的构造最多花费 `O(l)`，总时间复杂度为 `O(q · n log n · l)`；额外空间复杂度为 `O(n)`。题目中三者都不超过 100，直接排序足够。

## 边界条件与本地验证

- 采用字符串而不是转整数，前导 0 不会丢失。
- `trim` 可以等于完整长度，此时后缀就是原字符串。
- 相同裁剪值通过原下标打破平局。
- 已验证题面样例：第一组返回 `[2,2,1,0]`，第二组返回 `[3,0]`。
- 已验证边界：`["01","01"], [[1,1],[2,2]]` 返回 `[0,1]`。
