## 算法

固定初始积分 `x`，先解决可行性判定。

一个已经能从某个起点完整挑战的连续环区间称为“可行区间”。它当前能使用的积分是

```text
x | OR(区间内 challenge)
```

1. 所有 `challenge[i] <= x` 的单点都是可行区间。先用并查集合并相邻的可行单点。
2. 对每个可行区间检查左右边界。若边界点要求不超过该区间当前积分，就吸收此点。
3. 新点若碰到另一可行区间，立即合并两个区间；合并后的区间 OR 变大，重新入队检查边界。
4. 某个并查集连通块大小达到 `n` 时判定成功；队列耗尽则失败。

为什么相邻的两个可行区间一定可以合并？设左区间右端关卡要求为 `u`、完整挑战左区间后的积分为 `S_A`，右区间左端关卡要求为 `v`、完整挑战右区间后的积分为 `S_B`。由于端点都属于各自区间的 OR，已有 `S_A >= u`、`S_B >= v`。如果左区间不能接着挑战 `v`，则 `v > S_A >= u`；如果右区间也不能接着挑战 `u`，则 `u > S_B >= v`，两式矛盾。因此至少存在一个串联方向，合并后的整个区间仍可从一个起点完成。

判定的完备性也成立：任意真实挑战过程的已挑战集合始终是连续区间，其起始单点会在初始化中出现；上述闭包过程会包含它每一次合法的边界扩张。因此真实可行时，并查集闭包最终必然覆盖全环。

可行性不是关于普通数值大小的单调函数，不能数值二分；例如 OR 可能让较小初值获得更大的中间积分。改为从高位到低位确定最小答案：已确定高位前缀为 `answer` 时，令

```text
candidate = answer | ((1 << bit) - 1)
```

它是“当前位取 0”这一分支中的最大数。若 `candidate` 可行，则存在该分支答案，当前位保持 0；否则该分支的所有数都是 `candidate` 的按位子集，而可行性对“增加初始积分的 1 位”单调，所以当前位必须置 1。

## 正确性要点

- 单点初始化只加入真正可挑战的起点。
- 边界吸收保持“存在一个起点能完成整个区间”的不变量。
- 相邻可行区间由上述反证引理保证可以串联，故并查集合并合法。
- 闭包既不产生伪可行区间，也不会漏掉任何真实路径，固定 `x` 的判定充要。
- 逐位贪心利用按位包含关系上的单调性，得到数值最小的可行初始积分。

## 复杂度

设 `B = max(challenge).bit_length()`，题目中 `B <= 47`。一次判定中每个点至多被激活一次，每次合并为并查集近常数操作，时间 `O(n α(n))`、空间 `O(n)`。总时间 `O(B n α(n))`，空间 `O(n)`。

## 边界条件与本地验证

- `n = 1`：唯一关卡必须由初始积分直接满足。
- 所有关卡相同、多个初始可行区间、跨 `n-1/0` 的环形合并均包含在统一流程中。
- 反例 `[23,25,8,25]` 的真实最小值 `17`，新判定与完整状态枚举一致。
- 使用“枚举初始积分、起点和所有合法边界挑战顺序”的 oracle：对小值数组做系统穷举，并对长度 `1..10` 的大量随机数组逐个初值对拍；固定初值判定和最终最小答案均一致。
- 另外以 `n = 50000`、47 位随机数做性能测试，验证时间和内存规模符合约束。
