## 思路

任何非零数位的质因子都只可能是 `2、3、5、7`。先分解 `t`；若仍有其他质因子，直接返回 `-1`。

目标数与 `num` 等长时，若它不等于 `num`，一定存在最靠左的“增大位”：该位左侧保持不变，该位变大，右侧可自由取最小的可行非零后缀。因此从右向左枚举增大位，并从原数位加一开始枚举新数位；第一个可行方案就是数值最小的方案。若原串包含 `0`，增大位不能位于第一个 `0` 的右侧，否则这个 `0` 会被保留。

对固定前缀和新数位，只需判断剩余位置能否补足质因子需求。质因子 `5`、`7` 分别只能由数位 `5`、`7` 提供，所以它们各需要一个数位。对 `2`、`3` 的剩余指数，预计算二维表 `dp[a][b]`：补足至少 `a` 个 2 和 `b` 个 3 所需的最少数位数。状态规模很小（`t <= 10^14` 时指数分别不超过 46 和 29），每个状态枚举数位 `2..9`。

于是四元需求 `(a,b,c,d)` 的最短补全长度为：

```text
dp[a][b] + c + d
```

找到可行增大位后，再按数位 `2..9` 贪心构造一次后缀：选择仍能使最短长度恰好减少 1 的最小数位。这得到所有最短补全中字典序最小的串。剩余空位在它前面填 `1`，不会改变乘积且字典序最小。

若所有等长方案均不可行，则答案长度至少为 `n + 1`；取 `max(n + 1, 最短补全长度)`，在最短补全前填 `1` 即为答案。

## 正确性证明

1. 分解后的需求指数逐项不超过 0，当且仅当当前数位乘积包含 `t` 的全部质因子；若 `t` 含其他质因子，数位乘积不可能被它整除。
2. `dp[a][b]` 枚举首个补全数位并转移到扣除其贡献后的需求，因此覆盖所有由数位 `2..9` 组成的补全；取最小值即得到最少数位数。5 和 7 无法与其他允许质因子合并在一个数位中，所以总最短长度确为 `dp[a][b] + c + d`。
3. 构造后缀时，每一步选择满足“最短长度减少 1”的最小数位，既保持全局最短，又使当前位最小；归纳可得整个后缀是所有最短补全中字典序最小者。
4. 从右向左枚举增大位会尽量保留更长的原前缀；固定增大位后从小到大枚举新数位，并使用最小后缀。因此第一个可行的等长候选就是不小于 `num` 的最小无零答案。若没有等长候选，任何更长数字都更大，而构造出的最短可行长度及其最小字典序答案仍为全局最小。

## 复杂度

设 `n = len(num)`，2、3 在 `t` 中的指数分别为 `A、B`（约束下 `A <= 46, B <= 29`）。预计算为 `O(AB)` 时间和空间；前缀及候选扫描为 `O(n)` 时间，四个 `bytearray` 使用 `O(n)` 空间；后缀只构造一次且长度为 `O(log t)`。总时间 `O(n + AB)`，总空间 `O(n + AB)`。

## 本地验证

- 覆盖三个题目样例、包含零、`t = 1`、不可分解质因子、需要扩位等边界。
- 使用独立的小范围逐数枚举 oracle，对多组短字符串和 `t` 进行穷举对拍。
- 回归远程超时末例：`num = "23624785", t = 21504000`，结果应为 `"555678888"`。
- 使用长度 `200000` 的输入检查最大规模下的线性性能。
