## 根因

Terra 虽然声明使用双指针，但对每个递增后缀起点都执行 `left = 0`，然后重新扫描整个递增前缀。若数组由很长的递增前缀和递增后缀组成、中间只有一个断点，两个循环相乘会退化为 `O(n^2)`，导致超时。

## 思路

删除一个连续子数组后，剩余数组由两部分组成：原数组的一个前缀和一个后缀。结果严格递增需要同时满足：

1. 保留的前缀严格递增；
2. 保留的后缀严格递增；
3. 两边都非空时，前缀最后一个值严格小于后缀第一个值。

先找到最长严格递增前缀，末端为 `prefix_end`。若整个数组已经严格递增，任意非空删除区间都合法，直接返回 `n(n+1)/2`。

否则：

- 删除某个后缀、只保留递增前缀时，共有 `prefix_end + 2` 种选择（保留长度可以为 0 到 `prefix_end + 1`）。
- 再从右向左枚举所有严格递增后缀的起点 `suffix_start`。维护 `compatible_prefix_end`，使它是满足 `nums[p] < nums[suffix_start]` 的最大递增前缀下标；合法保留前缀末端可以是 `-1, 0, ..., p`，因此当前后缀贡献 `p + 2`。

后缀起点向左移动时，后缀首值严格变小，所以可兼容的前缀末端只可能向左移动，不需要为每个后缀从头扫描。

## 正确性证明

最长递增前缀涵盖了所有可能保留的非空前缀：若保留前缀越过 `prefix_end`，其中已经含有一个非递增相邻对，删除中间的一个连续区间无法修复保留前缀内部的这个对。同理，算法枚举的严格递增后缀恰好涵盖所有可能保留的非空后缀。

先统计只保留前缀的删除方案。随后固定一个枚举到的非空严格递增后缀。由于最长递增前缀本身严格递增，所有满足衔接条件的前缀末端必构成连续集合 `-1, 0, ..., compatible_prefix_end`：`-1` 表示不保留前缀，其余下标还需满足 `nums[p] < nums[suffix_start]`。这些选择各自唯一确定删除区间 `[p+1, suffix_start-1]`，并且三项严格递增条件全部成立；反之，任何保留该后缀的合法删除方案，其前缀末端必在这个集合中。因此贡献 `compatible_prefix_end + 2` 不重不漏。

不同后缀起点对应不同删除区间右端点，只保留前缀的方案则删除到数组末尾，与上述方案不重合。故累计结果恰为全部合法删除子数组数。

## 复杂度

前缀、后缀和兼容前缀指针都只单向移动，每个最多经过 `n` 个位置，时间复杂度为 `O(n)`；只使用常数个整数变量，额外空间复杂度为 `O(1)`。
