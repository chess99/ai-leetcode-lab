## 算法与思路

为了减少枚举次数，先让 `cost1` 表示两种文具中较贵的价格。枚举购买第一种文具的数量 `x`，范围为 `0..total // cost1`。

固定 `x` 后，剩余金额为 `total - x * cost1`，第二种文具可以买 `0..remaining // cost2` 支，因此对应 `remaining // cost2 + 1` 种选择。累加所有 `x` 的方案数即可。

## 正确性

任意合法购买方案都由一对非负整数 `(x, y)` 唯一表示。算法枚举了第一种文具所有可能的数量 `x`。对固定的 `x`，预算约束等价于 `0 <= y <= remaining // cost2`，算法计算的数量恰好覆盖全部合法 `y`，既不遗漏也不重复。

所以对所有 `x` 的方案数求和，得到的正是所有不同购买方案的数量。交换两种价格只改变枚举顺序，不改变方案集合。

## 复杂度

- 时间复杂度：`O(total / max(cost1, cost2))`，枚举较贵文具的购买数量。
- 空间复杂度：`O(1)`。

## 边界条件与本地验证

- 两种文具都买不起：仍有都买零支这一种方案。
- 预算恰好等于某种价格：会同时统计购买一支和不购买。
- 两种价格相等：不同的数量组合仍分别统计。
- 某种价格为 `1`：公式仍能覆盖全部数量。
- 本地验证覆盖两个题目样例，结果为 `9`、`1`，并覆盖价格相等、恰好花完和单位价格场景。
