## 远程失败证据与根因

- `terra-medium` 的首次提交在样例即输出空串。其累计结果以 `''` 为递归 CTE 锚点，MySQL 据此推断出零宽字符串列，后续累计结果无法正确保留。
- `sol-medium` 将锚点改成 `LOWER(content_text)` 后，远程结果为 `13 / 14`，但在可追溯反例 `foo--bar -baz lOO-daR-@Daz-` 上输出 `Foo--Bar -Baz Loo-Dar-@daz-`，期望是 `Foo--bar -baz Loo-dar-@daz-`。
- 根因是把任意 `-` 都当成可大写后继字符的分隔符。远程反例说明，连字符特殊规则只适用于整个空格分词严格匹配 `^[A-Za-z]+-[A-Za-z]+$` 的情况，即恰好两个非空纯英文字母片段由一个连字符连接。前导/尾随连字符、连续连字符、额外连字符或混入其他特殊字符时，整个词都应退回普通规则：只尝试大写词的第一个字符，其余字母小写。

## 算法

采用“字符扫描 + 当前词分类状态”的递归 CTE：

1. 对整行执行 `LOWER(content_text)`，得到长度不变、列宽继承自原字段的工作串。
2. 用空格定位当前词；以大小写敏感正则 `^[A-Za-z]+-[A-Za-z]+$` 判断它是否是需要双首字母大写的简单连字符词，并把判断结果作为递归状态。
3. 从左到右扫描每个字符。当前位置为整行开头或紧跟空格时，将该位置大写；只有当前词通过上述完整匹配且当前位置紧跟连字符时，才额外将该位置大写。其他位置保持全小写工作串中的字符。
4. 每扫描到一个空格，就对空格后的下一个词重新分类；连续空格会依次产生空词状态，但空格自身原样保留。
5. 扫描完成后返回 `content_id`、原文本和转换结果，并按 `content_id` 排序。

## 正确性证明

将每个最大非空格子串称为一个词。先看任意一个词 `w`。

- 初始化将 `w` 的所有字母变成小写，不改变任何非字母字符。
- 若 `w` 不匹配 `^[A-Za-z]+-[A-Za-z]+$`，递归状态为假。算法只在 `w` 的第一个字符处执行一次大写，之后即使遇到连字符也不会触发大写。因此它恰好执行普通规则。
- 若 `w = x-y` 且 `x`、`y` 都是非空纯英文字母串，递归状态为真。算法会大写 `x` 的首字符，并在唯一连字符后大写 `y` 的首字符；其余字母保留初始化后的小写。因此结果恰为 `Capitalize(x)-Capitalize(y)`。

两种情况覆盖所有词，所以每个词都按题意转换。递归在扫描到空格时才更新词分类状态，故一个词的分类在其全部字符上保持不变，且不会错误影响相邻词。

最后，算法始终只原位替换单个字符，`LOWER`、`UPPER` 不改变题目字符集中的非字母字符，也不插入或删除字符；所以字符顺序、所有空格和其他格式均保持不变。综上，最终结果正确。

## 复杂度

设一行文本长度为 `n`。递归执行 `n` 轮；原位字符串替换最坏为 `O(n)`。每次进入新词时还会截取余串并做一次正则完整匹配，所有词的匹配长度总和不超过 `n`，但余串截取保守按每次 `O(n)` 计。因此总时间复杂度保守为 `O(n²)`。

递归工作状态保存一个长度为 `n` 的结果串。若 MySQL 物化全部 `n + 1` 个递归状态，最坏中间空间为 `O(n²)`；单个当前状态及最终结果为 `O(n)`。

若所有行长度分别为 `n_i`，总时间和最坏物化空间均为 `O(Σ n_i²)`。

## 边界条件

- 空字符串：不进入递归轮次，直接返回空字符串。
- `NULL`：`LOWER(NULL)` 仍为 `NULL`，最终筛选用长度 `0` 处理该情况，保留原行并返回 `NULL`。
- 最大长度：归档表结构为 `VARCHAR(255)`，最多递归 255 轮，低于 MySQL 8 默认的 1000 层递归上限。
- 单字符和全大写文本：先统一小写，再只尝试大写词首字符。
- 多个空格及首尾空格：每个空格都作为独立字符扫描并原样保留。
- 简单连字符词：`a-b`、`TOP-rated` 匹配完整模式，两部分分别大写。
- 非简单连字符词：`foo--bar`、`-baz`、`foo-`、`a-b-c`、`loo-dar-@daz-` 均退回普通规则，不大写连字符后的字符。
- 其他特殊字符：`@`、`/`、`^`、`,`、反斜杠等不被大小写函数改变；若混入连字符词，会使其不满足简单连字符模式。
